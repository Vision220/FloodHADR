# PHASE 24 — FLOOD PATH AUDIT & ROOT CAUSE ANALYSIS

## 1. Executive Summary & Incident Investigation
During Phase 24 audit, a critical discrepancy was identified in the displayed 2D/3D flood wave propagation path:
The flood inundation corridor was observed jumping away from the real downstream Bhagirathi river channel and heading east across mountain ridges towards an artificial/imaginary route (`[78.6100, 30.1500]`).

---

## 2. Root Cause Audit Breakdown

### 2.1 Component & Source File Audit
* **PATH SOURCE**:
  1. `frontend/src/data/gisSampleData.ts` (`sampleFloodDepthGeoJSON` hardcoded polygon coordinates)
  2. `frontend/src/components/map/GISMapModule.tsx` (Default GeoJSON layer data fallback)
  3. `frontend/src/simulation/PrototypeFloodModel.ts` (Straight Z-axis distance function $z - (-30)$)
  4. `backend/app/simulation/golden_benchmark_service.py` (Synthetic diamond DEM `450 + (abs(r-15)+abs(c-15))*18.5`)
  5. `backend/app/gis/gis_2d_service.py` (Fallback static GeoJSON polygons)

* **PATH DATA**:
  - Hardcoded GeoJSON Polygons in `gisSampleData.ts`:
    - Zone 1: `[[[78.4802, 30.3781], [78.4900, 30.3400], [78.5100, 30.2600], [78.4800, 30.2500], [78.4600, 30.3300], [78.4802, 30.3781]]]`
    - Zone 2 (Divergent path): `[[[78.5100, 30.2600], [78.6100, 30.1500], [78.5700, 30.1300], [78.4800, 30.2500], [78.5100, 30.2600]]]`
  - Note: `[78.6100, 30.1500]` lies far East of Devprayag and the Bhagirathi river valley, causing the flood polygon to jump over high-elevation mountain terrain.

* **PATH GENERATION METHOD**:
  - Static GeoJSON polygon array scaling via linear factor `prog * modelScale`.
  - Prototype 3D depth formula using orthogonal Z-distance `getWaterDepthAt(x, z)`.

* **HYDRAULIC SOURCE**:
  - Previous visualization was consuming static sample GeoJSON rather than the dynamic output of the 2D Shallow Water Equations (SWE) / Diffusive Wave Equation (DWE) solver.

* **DEM SOURCE**:
  - ALOS PALSAR 12.5m DEM (`data/ALOS_PALSAR_12M_REAL.tif`) was present in backend, but frontend defaulted to static polygons and backend test service defaulted to synthetic diamond grid `abs(r-15)+abs(c-15)`.

* **RIVER SOURCE**:
  - Real Bhagirathi River reach centerline (`sampleRiverGeoJSON`) in `gisSampleData.ts`:
    `[[78.4802, 30.3781], [78.4850, 30.3500], [78.4980, 30.2780], [78.5200, 30.2000], [78.5986, 30.1458], [78.3880, 30.1380], [78.2950, 30.1050], [78.1600, 29.9500]]`
  - The static flood polygon deviated from this centerline at $30.26^\circ\text{ N}$.

* **FRONTEND OR BACKEND**:
  - Both frontend mock fallback datasets and backend benchmark synthetic DEM solver initialization contributed to the issue.

* **STATIC OR DYNAMIC**:
  - Static polygon scaling in UI fallback, causing artificial jump across terrain.

* **REAL / DERIVED / SYNTHETIC**:
  - Classified as `SYNTHETIC / DEMO DATA FALLBACK`.

---

## 3. Required Fixes & Architecture Modifications

1. **Remove Artificial Flood Path Generation**:
   - Strip static mock polygons from active scientific simulation mode. Mark any legacy mock data explicitly as `DEMO_ONLY`.
   - Ensure the 2D map consumes dynamic raster grid simulation results generated by the 2D SWE/DWE solver over real DEM terrain.

2. **Real DEM & Terrain Gradient Driven Flow**:
   - Utilize real ALOS PALSAR 12.5m DEM surface $Z_{\text{terrain}}(x,y)$.
   - Compute water surface elevation $WSE(x,y,t) = Z_{\text{terrain}}(x,y) + h(x,y,t)$.
   - Compute velocity vector components $(u, v)$ and flow direction angle $\theta = \text{atan2}(v, u)$.

3. **Coordinate Reference System (CRS) Alignment**:
   - Ensure strict transformation between `EPSG:32644` (UTM Zone 44N) and `EPSG:4326` (WGS84 Lat/Lng).
   - Ensure grid cell $(r, c)$ maps accurately to river channel geometry.

4. **Synchronized `SimulationFrame` Architecture**:
   - Both 2D map and 3D digital twin must consume identical `SimulationFrame` objects for every timestep $T+0\text{ min} \dots T+360\text{ min}$.

5. **Hydraulic Debug Mode**:
   - Add developer/scientific debug layers showing Terrain, River Centerline, Dam, Breach, Wet Cells, Flood Extent, Velocity Vectors, Flow Direction, Water Surface, Contours, HEC-RAS Extent, FloodHADR Extent, and numerical stats overlay.
