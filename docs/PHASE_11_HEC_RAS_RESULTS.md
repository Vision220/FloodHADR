# PHASE 11 — HEC-RAS RESULT IMPORTER

## Executive Summary

Phase 11 establishes an authoritative **HEC-RAS Result Importer** within FloodHADR. This subsystem ingests native USACE HEC-RAS 2D simulation outputs (HDF5 `.p01.hdf` files, plan execution records, and benchmark reference rasters), extracting complete hydraulic field data and normalizing them into FloodHADR's standard `SimulationFrame` and `SimulationRun` structures.

The importer enforces spatial normalization (CRS and grid resolution alignment) while upholding strict **scientific integrity mandates** — HEC-RAS outputs are imported without post-hoc numerical modifications or artificial tuning to force agreement with FloodHADR's native 2D hydrodynamic solver.

---

## Imported Output Variables Matrix

The HEC-RAS Result Importer extracts seven core hydraulic output sets:

| Output Dataset | Scientific Description | Native Unit / Format | Normalized FloodHADR Format |
| :--- | :--- | :--- | :--- |
| **Maximum Depth** | Peak inundation water depth matrix across domain | Meters ($\text{m}$) | `summary_rasters.max_depth_matrix` ($2\text{D Array}$) |
| **Maximum Velocity** | Peak depth-averaged flow velocity magnitude | Meters / sec ($\text{m/s}$) | `summary_rasters.max_velocity_matrix` ($2\text{D Array}$) |
| **Water Surface Elevation** | Peak water surface elevation ($z_w = z_{bed} + h$) | Meters above MSL ($\text{m}$) | `summary_rasters.water_surface_elevation_matrix` |
| **Arrival Time** | Flood wave arrival time relative to dam failure | Minutes ($\text{min}$) | `summary_rasters.arrival_time_matrix` |
| **Inundation Extent** | Spatial boundary of wet area ($h > 0.05\,\text{m}$) | Polyline / Grid | `inundation_extent_geojson` & `flooded_mask` |
| **Gauge Hydrographs** | Stage ($H(t)$) and Flow ($Q(t)$) time series at key nodes | $\text{m}^3/\text{s}$ & $\text{m}$ | `hydrograph` (Dam Toe, Koti Nala, Devprayag) |
| **Time-Series Frames** | Sequential snapshot frames ($t=0\text{h}$ to $t=6\text{h}$) | Time-stamped grids | `List[SimulationFrame]` |

## Spatial Normalization Architecture

Before cross-model comparison (e.g. FloodHADR 2D vs HEC-RAS 2D in Phase 12), the importer aligns spatial geometry:

1. **CRS Normalization:** Re-projects native spatial bounding boxes and GeoJSON polygons to target domain CRS (`EPSG:32644` UTM Zone 44N / WGS84).
2. **Grid Resolution Normalization:** Resamples imported raster matrices to target grid resolution ($25.0\,\text{m} \times 25.0\,\text{m}$, $30 \times 30$ domain matrix) via bilinear grid sampling, preserving spatial bounding alignment.

### Spatial Normalization Record

```json
"spatial_normalization": {
  "original_crs": "EPSG:32644",
  "normalized_crs": "EPSG:32644",
  "crs_status": "NORMALIZED_MATCH",
  "target_resolution_m": 25.0,
  "target_grid_shape": [30, 30],
  "bounding_box_utm": [0.0, 0.0, 750.0, 750.0],
  "normalization_method": "Bilinear Grid Alignment & CRS Reprojection"
}
```

## Scientific Integrity Mandate

> [!IMPORTANT]
> **NO RESULT MUTATION / NO ARTIFICIAL AGREEMENT**
> 
> HEC-RAS results are imported strictly as generated by the USACE HEC-RAS engine. FloodHADR does **NOT** apply post-hoc scaling factors, artificial smoothing, or bias corrections to alter HEC-RAS outputs to artificially match FloodHADR 2D solver predictions. Differences between models remain transparently preserved for scientific evaluation.

## REST API Integration

HEC-RAS result importing is exposed via FastAPI:

- `POST /api/v1/hecras/import`: Ingests HEC-RAS plan outputs and returns normalized `SimulationRun` payloads containing spatial matrices, hydrographs, and time-series `SimulationFrame` sequences.
